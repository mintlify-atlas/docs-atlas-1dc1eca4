Every Sheet JSON object has a canonical JSON shape that `class-transformer` reads and writes via `instanceToPlain` and `plainToInstance`. Knowing this shape lets you write tests against raw JSON payloads, store workbooks in document databases, build API integrations, and construct workbook objects in environments that do not use the Node.js SDK at all.

## Workbook JSON

A serialized `Workbook` is a JSON object with four top-level keys. The `@entity` field is the discriminator that identifies the object type; `name` carries the workbook's display name; `metadata` holds any user-defined key-value annotations; and `sheets` is an ordered array of serialized `Sheet` objects.

```json
{
  "@entity": "workbook",
  "name": "workbook",
  "metadata": {},
  "sheets": []
}
```

| Key | Type | Source |
|---|---|---|
| `@entity` | `"workbook"` | `BaseObject.getEntity()` — reads `@Reflect.metadata('@entity', 'workbook')` from the constructor |
| `name` | `string` | `BaseObject.getName()` — reads `@Reflect.metadata('name', 'workbook')` from the constructor |
| `metadata` | `object` | `BaseObject.getMetadata()` — serializes the `JSONObject` metadata bag; `{}` when unset |
| `sheets` | `Sheet[]` | `Workbook.sheets` — ordered array of serialized sheet objects |

## Sheet JSON

Each entry in the `sheets` array is a serialized `Sheet` object. Its `blocks` array holds the block objects that belong to this sheet, each identified by its own `@entity` field.

```json
{
  "@entity": "sheet",
  "name": "Q1 Report",
  "metadata": {},
  "blocks": []
}
```

| Key | Type | Description |
|---|---|---|
| `@entity` | `"sheet"` | Identifies the object as a `Sheet` |
| `name` | `string` | Sheet display name. During XLSX export, the last segment after the final `.` is used as the Excel tab name and trimmed to 31 characters |
| `metadata` | `object` | User-defined sheet-level annotations |
| `blocks` | `Block[]` | Ordered array of serialized `Table` and/or `List` block objects |

## Table block JSON

A `Table` block serializes its column names into a flat `header` array and its row data into a nested `rows` array. Each inner array in `rows` holds cell values in the same positional order as `header`.

```json
{
  "@entity": "table",
  "name": "Revenue Table",
  "metadata": {},
  "header": ["id", "product", "price"],
  "rows": [
    [1, "Widget A", 9.99],
    [2, "Widget B", 14.99],
    [3, "Widget C", 4.49]
  ]
}
```

| Key | Type | Description |
|---|---|---|
| `@entity` | `"table"` | Discriminator — tells `class-transformer` to instantiate `Table` |
| `name` | `string` | Block display name (also written as the first row in the XLSX sheet during export) |
| `metadata` | `object` | User-defined block-level annotations |
| `header` | `JSONValue[]` | Flat array of column name strings |
| `rows` | `JSONValue[][]` | Array of row arrays; each inner array aligns to `header` by position |

Cell values in `rows` can be `string`, `number`, `boolean`, or `null`. Columns whose header name contains the substring `'epoch'` receive special handling during XLSX import and export: epoch millisecond timestamps are automatically converted to and from ISO 8601 date strings in spreadsheet cells.

## List block JSON

A `List` block serializes its items as an array of **single-key objects** — each element contains exactly one key-value pair. This compact format is intentionally different from `[{"key": "...", "value": "..."}]`: the item key becomes the JSON property name, and the item value becomes the property value.

```json
{
  "@entity": "list",
  "name": "config list",
  "metadata": {},
  "items": [
    { "environment": "production" },
    { "version": "3.1.0" },
    { "max_retries": 5 },
    { "debug_mode": false }
  ]
}
```

| Key | Type | Description |
|---|---|---|
| `@entity` | `"list"` | Discriminator — tells `class-transformer` to instantiate `List` |
| `name` | `string` | Block display name; **must end with `'list'`** (case-insensitive) for XLSX import to treat the block as a `List` rather than a `Table` |
| `metadata` | `object` | User-defined block-level annotations |
| `items` | `{ [key: string]: JSONValue }[]` | Each element is a single-key object mapping one key to its `JSONValue` |

The name constraint for XLSX import comes from `WorkbookConverter.parseBlock()`, which inspects the first cell of each detected block range: if `name.toLowerCase().endsWith('list')` is `true`, the block is parsed as a `List`; otherwise it is parsed as a `Table`.

## The @entity discriminator

The `@entity` property is the mechanism that makes polymorphic deserialization of the `blocks` array possible. When `class-transformer` processes a `Sheet`, it reads the `@entity` field of each plain block object and decides which constructor to call:

```
blocks[n]["@entity"] === "table"  →  instantiate Table
blocks[n]["@entity"] === "list"   →  instantiate List
```

This mapping is declared in `Sheet` via a `@Type` discriminator on the `blocks` property:

```typescript
@Type(() => Block, {
  keepDiscriminatorProperty: true,
  discriminator: {
    property: '@entity',
    subTypes: [
      { value: Table, name: SheetJsonEntityType.TABLE }, // 'table'
      { value: List,  name: SheetJsonEntityType.LIST  }, // 'list'
    ],
  },
})
blocks?: Array<Block>;
```

The `SheetJsonEntityType` enum defines the complete set of recognized entity strings:

```typescript
export enum SheetJsonEntityType {
  WORKBOOK             = 'workbook',
  SHEET                = 'sheet',
  LIST                 = 'list',
  TABLE                = 'table',
  ISSUE_ROW            = 'table.issue_row',
  ISSUE_TABLE          = 'table.issue_table',
  ISSUE_ROW_FOR_LIST   = 'list.issue_row',
  ISSUE_TABLE_FOR_LIST = 'list.issue_table',
}
```

The four `issue_*` variants are reserved for validation-error payloads and are not produced by normal serialization.

`keepDiscriminatorProperty: true` ensures that the `@entity` string is retained on the deserialized instance. Without it, a subsequent `instanceToPlain` call would omit the discriminator and the JSON would become undeserializable on the next round-trip.

## Complete example

The following JSON object represents a workbook with one sheet containing both a `Table` block and a `List` block. This is the exact shape produced by calling `instanceToPlain(workbook, { excludeExtraneousValues: true })`.

```json
{
  "@entity": "workbook",
  "name": "workbook",
  "metadata": {},
  "sheets": [
    {
      "@entity": "sheet",
      "name": "Q1 Report",
      "metadata": {},
      "blocks": [
        {
          "@entity": "table",
          "name": "Revenue Table",
          "metadata": {},
          "header": ["id", "product", "price", "created_epoch"],
          "rows": [
            [1, "Widget A", 9.99, 1704067200000],
            [2, "Widget B", 14.99, 1706745600000],
            [3, "Widget C", 4.49, 1709251200000]
          ]
        },
        {
          "@entity": "list",
          "name": "Report Config list",
          "metadata": {},
          "items": [
            { "generated_by": "analytics-service" },
            { "period": "Q1-2024" },
            { "currency": "USD" },
            { "include_tax": true }
          ]
        }
      ]
    }
  ]
}
```

Points worth noting in this example:

- The `Table` block has a `created_epoch` column. During XLSX export, `WorkbookConverter` automatically converts those millisecond timestamps to ISO 8601 strings in the spreadsheet cells; during XLSX import, ISO 8601 strings in `epoch`-named columns are parsed back to millisecond numbers.
- The `List` block name ends with `'list'` (case-insensitively). This is the cue `WorkbookConverter.parseBlock()` uses to parse the block as a `List` when reading from XLSX, rather than a `Table`.
- The `metadata` field is an empty object `{}` on every node. It is always present in the serialized form because `getMetadata()` is annotated with `@Expose({ name: 'metadata' })` in `BaseObject`.
